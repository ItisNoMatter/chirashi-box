# 0007: 「重い」の原因を測って突き止め、リージョンと画面の両方で直した

- Date: 2026-10-13
- Related AnyDR: AnyDR 0031

## Objective
「動作が重く感じる」というフィードバックに応える。ユーザーの案は「タップしたらすぐ遷移し、ロード中はプレースホルダーカードを出す」。この案が効くかを確かめ、効くなら実装する。

## Action
- コードを確認した。各ページはすでに Suspense で包まれていて、`cacheComponents` と `partialPrefetching` も有効だった。「すぐ遷移して仮の表示を出す」骨組みは半分できており、fallback が「読み込み中…」の1行だけという状態だった。
- 本番を curl で測った。枠が届いてからデータの部分が届くまで、毎回約0.85秒かかっていた。データベースへの問い合わせは並べて1往復だったので、Vercel の Function Region（既定のアメリカ東部）と Supabase（東京）の距離を疑った。私からは Vercel を確認できないので、ユーザーにダッシュボードで確かめてもらった。
- ユーザーが region を東京（hnd1）に変えて再デプロイした。測り直すと、ページ全体の受け取りが1.0〜3.9秒から0.24〜0.42秒に縮んだ。
- 画面の側も直した。タブとエリアのチップは、押した瞬間に選択の表示を切り替え、データが届くまでグリッドを仮のカードにした（useOptimistic と useTransition）。各ページの fallback は、読み込み後と同じ形のプレースホルダーに置き換えた。
- 手元で本番と同じ形にビルドし、ブラウザで動きを確かめた。そのあと本番にデプロイした（コミット 0486da9）。

## Result
- サーバー側：表示までがおよそ1秒から0.3秒になった。しばらくアクセスがなかったあとの最初の1回は、今も0.8〜1.1秒かかる。
- 画面側（手元の確認）：タブを押してから表示が変わるまで約9ミリ秒、チラシを押してから詳細の仮の表示が出るまで約5ミリ秒。
- iPhone での体感の確認はこれから。

## Reflections
- 最初に出された案（プレースホルダー）は正しい方向だったが、いちばん効いたのはコードの外にある1つの設定（Function Region）だった。体感の改善に手をつける前に、どこで時間を使っているかを測ったことで、それに気づけた。
- 再デプロイの直後に測ったときは、まだ約1秒かかっていた。古いサーバーがしばらく応答していたためで、ここで「region は効かなかった」と結論しかけた。計測の方法を変えて（チャンクが届くタイミングを1つずつ見て）測り直し、正しい数字が出た。設定を変えた直後の計測は、時間をおいてもう一度確かめるべき。
- 同じページの中で searchParams だけが変わる切り替えでは、一度表示された Suspense は fallback を出し直さない。そのため、押しても反応がないように見えていた。Next.js が用意している仕組み（loading.tsx や Suspense の fallback）だけでは、このケースは埋まらない。
