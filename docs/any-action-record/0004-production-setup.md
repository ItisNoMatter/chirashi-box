# 0004: 本番の環境（Supabase・APIキー・認証メール・巡回）をセットアップした

- Date: 2026-10-11
- Related AnyDR: 0008, 0011, 0020, 0024

## Objective
本人にしかできない作業（APIキーの取得、本番のSupabaseの作成、Secretsの登録）を済ませ、本番のDBと認証、毎晩の巡回が動く状態にする。

## Action
- 対話形式で1ステップずつ進めた。ウィザードのスクリプトにはしなかった。想定外のトラブルが起きたときに、スクリプトを直して再実行する出戻りが大きいため（ユーザーの判断）。
- AnthropicのAPIキーを取得した。Google CloudでPlaces API (New)を有効にし、キーをPlaces API (New)専用に制限して、Text SearchとPlace Detailsに1日100回の上限を設けた。
- 本番のSupabaseを東京リージョンに作り、`supabase link` と `db push` でマイグレーション5つを適用した（`--dry-run` で一覧を示し、承認を得てから適用）。
- 認証の設定は `supabase config push` を使わず、Management APIで必要な項目だけを変更した。
- 無料プランではテンプレートを変更できないと分かったため、Brevoを外部のSMTPとして設定した（AnyDR 0024）。
- 本番からテストのメールを送り、確認コードが受信トレイに届くことを確かめた。巡回のワークフローを手動で実行し、成功を確かめた。

## Result
- 本番のSupabase：マイグレーション適用済み。匿名サインイン有効、メールの確認が必要、6桁のコード、Brevo経由で送信。
- GitHub Secrets：`ANTHROPIC_API_KEY`、`CRAWLER_CONTACT`、`SUPABASE_URL`、`SUPABASE_SECRET_KEY` を登録済み。巡回のワークフローは成功（巡回対象0件）。
- 本番の値は `.env.production.local`（リポジトリ外）にまとめた。

## Reflections
- `supabase config diff` で差分を見てから進めたのが効いた。`config push` は、ローカル開発用の値（メールの送信間隔1秒、`site_url` が127.0.0.1、二段階認証の無効化など）まで本番に送ってしまい、しかも認証の設定はまとめてしか承認できない。必要な項目だけをManagement APIで変更する形に切り替えた。
- Supabaseの無料プランで組み込みのメール送信サービスを使うと、メールのテンプレートを変更できない。この制限は、本番に設定しようとして400が返るまで分からなかった。ローカルではテンプレートを自由に変えられるため、ローカルで動いたことが本番で動く保証にならない。Placesの規約（0020）に続き、外部サービスの制約は、本番に当ててみるまで見えないことがある。
- `! gh secret set NAME` は入力待ちにならず、空の値のSecretが登録されていた。Secretの値は後から読めないので、更新日時だけでは中身が正しいかを判断できない。ローカルのファイルから標準入力で渡す形に切り替え、値を画面に出さずに登録し直した。
- 無料のGmailのアドレスを送信元にすると、Brevoでも警告（DKIM、DMARC）が出た。それでも、テスト送信は受信トレイに届いた。利用者が増えたり届かなかったりした場合は、独自ドメインを取って認証するのが次の手になる。
