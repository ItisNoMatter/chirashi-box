# 0002: 核の画面（眺める → 気になる → マイページ）を実装した

- Date: 2026-10-11
- Related AnyDR: 0014, 0015, 0019

## Objective
MVPの核である「展示を眺める → 気になるをマークする → マイページにチラシが並ぶ」を、ローカルのSupabaseにつないで最後まで動かす。

## Action
- 匿名ユーザーをいつ作るかをgrillで決めた（AnyDR 0019：初めて「気になる」を押した時点で作る）。
- Supabaseのクライアント（サーバー用・ブラウザ用）と、セッションを更新する `proxy.ts` を書いた。
- 眺める（開催中／もうすぐのタブ、エリア絞り込み、「あと◯日」の札）、展示の詳細、マイページ（3つの区切り、本人だけが見られる）、気になるボタン（Server Action）、チラシ（館の画像を直接表示し、なければ自動生成）を実装した。
- 詳細ページに公式ページへのリンクを出すため、`exhibitions.official_url` のマイグレーションを追加した。ローカル開発用の架空データ（`seed.sql`）も用意した。
- ブラウザの自動操作とcurlで動作を確かめ、見つかった問題を直した。ユーザーから指摘を受け、「あと◯日」の札をチラシに重ねるのをやめ、タイトル行の先頭に移した。

## Result
- 眺める → 気になる → マイページが最後まで動いた（コミット `69f182e`）。最初に押したときの匿名ユーザーの作成、もうすぐのタブからの「気になる」、外した結果の反映を、ブラウザで確認した。
- 単体テスト16件、RLSのテスト9件、型チェック、lint、本番ビルドがすべて通った。
- 他人のマイページは、ストリーミングのためHTTPステータスは200のまま、not-foundの画面になる（中身は漏れない）。

## Reflections
- `create-next-app`（Next.js 16.4）は、Cache Components（`cacheComponents: true`）を既定で有効にしていた。「明示的に有効にしない限り使われない」と思い込んで書いたため、`new Date()` やSupabaseの `getClaims()`（中で現在時刻を読む）が「プリレンダー中の不安定な値」としてエラーになった。リクエスト時の値は `connection()` で宣言し、ページの中身を `<Suspense>` で包む、というCache Componentsの作法に合わせて直した。ドキュメントだけでなく、生成された `next.config.ts` を最初に読むべきだった。
- 最初の失敗では、2回目以降の「気になる」がサーバーに届いていなかった。原因はアプリのロジックではなく、エラーで出た開発用のオーバーレイがクリックを奪っていたこと。サーバーのログでPOSTの有無を確かめたことで、早く切り分けられた。
- `<Suspense>` を入れた後、ブラウザでは「読み込み中…」のまま止まって見えた。しかしcurlで取ったHTMLには中身が届いていた。自動操作のタブがバックグラウンド（`visibilityState: hidden`）にあり、Reactがストリーミングされた中身を差し替えるときに待つ `requestAnimationFrame` が発火していなかった。スクリーンショットがタイムアウトし続けたのも同じ原因だった。アプリのバグと環境の制約を取り違えないよう、HTMLの中身・可視状態・rAFの発火を順に確かめるのが有効だった。
- 「あと◯日」の札をチラシに重ねると、自動生成カードのタイトルも、館の画像（作品）も隠してしまう。チラシの上には何も重ねない、という見た目の方針は、0007（トリミングしない、加工しない）とも揃っている。
