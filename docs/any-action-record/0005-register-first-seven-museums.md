# 0005: 最初の巡回対象7館を登録し、実際のサイトに合わせて巡回を直した

- Date: 2026-10-12
- Related AnyDR: 0025, 0026

## Objective
ういぴさんが指定した7館（国立西洋美術館、国立新美術館、三菱一号館美術館、東京都美術館、森美術館、東京都現代美術館、アーティゾン美術館）を、本番の巡回対象にする。毎晩の巡回で LLM を実際に呼び始める前に、料金と取れ方を確かめる。

## Action
- 7館の robots.txt と利用規約を確認した。リンクや画像に制限のある3館（国立西洋美術館、三菱一号館美術館、森美術館）に合わせて、ドメインごとの制限を表示のときに当てはめる仕組みを、テストから書いて作った（AnyDR 0025）。
- 7館の place_id を Places で引き、住所は各館の公式サイトから取った（0020）。会場、巡回対象、制限を本番に登録した。
- 巡回のログに、Claude API のトークン使用量を出すようにした。
- 1館だけをローカルで巡回して料金を測った。問題が見つかったので、今夜の巡回を止めて直した（AnyDR 0026）。
  - リンク選びの LLM に今日の日付を渡し、終わった展示を選ばせないようにした。
  - 一覧が JSON の場合も、リンクを拾えるようにした（東京都現代美術館）。
  - ページに `<main>` があれば、それを本文にするようにした（国立西洋美術館）。
  - 国立西洋美術館は、巡回対象を `current.html` と `upcoming.html` の2つに分けた。
- 7館をローカルで最初から巡回し直して確かめてから、本番に反映し、push して巡回を再開した。

## Result
- 東京都美術館の1館の初回は、APIを133回呼んで約$2.3、から、9回で約$0.14に下がった。
- 7館の初回は約$1になった（APIを67回、約3分半）。登録された38件は、すべて開催中かこれからの展示だった。
- テスト72件、pgTAP 12件が成功した。コミット `2718149` を push し、巡回のワークフローを有効に戻した。

## Reflections
- 料金を測るつもりで1館だけを走らせたら、料金より先に取れ方の問題が3つ見つかった（過去の展示を全部読む、JSON で組み立てる一覧、Readability の誤り）。架空のページで書いたテストはすべて通っていたが、実際のサイトは、テストで想定した「一覧ページからリンクをたどる」作りを、いろいろな形で外れていた。本番に入れる前に、実際のサイトでローカルから一度走らせる工程は、今後館を追加するときも残すべきだと思う。
- 東京都美術館の123件のうち117件が終わった展示で、料金の9割以上が「誰も見ない展示」を読むのに使われていた。トークンの集計をログに出さなければ、件数が多いのは「よく取れている」ように見えていたかもしれない。
- Readability は記事向けの道具で、美術館のページのように「見出しと会期の表 + 解説文」に分かれた作りでは、解説文だけを選んだり、クッキーの案内を選んだりする。テストで再現しようとした最初の架空ページでは、Readability が正しく読めてしまった。失敗を再現するには、実際のページの形（本文の外に長い案内文がある）を写す必要があった。
- 本番の DB への操作は、ユーザーが承認していても、操作ごとに自動モードに止められることがあった。承認の範囲（どの行をどう変えるか）を具体的に示してから実行すると通った。
