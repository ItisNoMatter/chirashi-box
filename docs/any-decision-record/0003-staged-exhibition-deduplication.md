# 0003: 展示の重複判定を「URL → 同会場・会期重複の候補照合 → 新規」の段階的照合にする

- Date: 2026-10-10
- Status: Accepted
- Category: architecture
- Deciders: the user, Claude Code

## Context
巡回とURL登録の両方が `exhibitions` にupsertするため、同じ展示かどうかの判定キーが必要になった。展示は「1つの会場 × 1つの会期」と定義しており（CONTEXT.md）、同じ展示に館のページと特設サイト（共催の新聞社・テレビ局など）の複数のURLがあるケースが実際に存在する（例：国立新美術館のルーヴル展は、日本テレビの特設サイトにリンクしている）。

## Decision
次の順で照合する。
1. 取得元のURLが `exhibition_sources` に既にあれば、その展示として扱う。
2. なければ、同じ会場で会期が重なる展示を候補とし、正規化した展示名が一致するか、一方が他方を含んでいれば、その展示に紐づける。
3. 該当がなければ新しい展示として登録する。

1つの展示は複数の取得元URL（`exhibition_sources`）を持てる。

## Alternatives
- 公式URLを一意キーにする: 館のページと特設サイトが別々の展示として二重登録され、「紹介ページが複数あっても1つの展示」という定義が成り立たない。館がサイトを改装してURLが変わった場合も二重になる。
- 自然キー（会場 + 正規化した展示名 + 開始日）を一意にする: LLMの抽出結果は表記が揺れる（「」の有無、サブタイトル、全角と半角）ため、完全一致では二重登録が起きやすい。

## Consequences
- 照合ロジックが3案の中で一番多く、テストが必要になる。
- すり抜けた重複は残りうる。MVPは招待制の小さな運用なので、当面はSupabaseのダッシュボードで手作業でマージし、マージ用の画面は作らない。
- 特設サイトのURLから会場をどう決めるか、`venues` にない会場をどう扱うかは、別途決める必要がある。
