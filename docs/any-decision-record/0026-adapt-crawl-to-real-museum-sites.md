# 0026: 実際の7館に合わせて、巡回の読み方を直す（終わった展示を選ばない、JSON の一覧、`<main>` を本文にする）

- Date: 2026-10-12
- Status: Accepted
- Category: architecture
- Deciders: the user, Claude Code

## Context
ういぴさん指定の7館（0025）を、本番に入れる前にローカルで巡回して料金を測った。次の3つの問題が見つかった。
- 東京都美術館の1館だけで、APIを133回呼び約$2.3かかった。登録した123件のうち117件は、会期が終わった展示（古いものは2012年）だった。一覧ページに過去の展示へのリンクも並んでいて、リンク選びがそれも選んでいた。
- 東京都現代美術館は、一覧を `/json/exhibitions/exhibitions.json` から JavaScript で組み立てている。そのため、HTML からはリンクが1本も取れなかった。
- 国立西洋美術館では、Readability が本文の選び方を誤った。解説文だけを選んで展示名・会期を落としたり、クッキーの案内を本文と取り違えたりした。また、一覧の URL は `current.html` へ移るだけのページで、今後の展示は `upcoming.html` に別に載っていた。

## Decision
- リンクを選ぶ LLM に今日の日付を渡す。リンクの文字や URL の年・日付から、明らかに終わったと分かる展示は選ばせない。分からないものは選ばせる。
- 一覧が JSON の場合は、同じサイトのページを指す値を探す。同じ項目の文字（展示名・会期など）を添えて、HTML の場合と同じリンク選びに渡す。一覧のハッシュは JSON の本文そのものから作る。JSON を受け付けるのは巡回の一覧だけで、URL登録と詳細ページでは受け付けない。
- ページに `<main>` があれば、そこから `script` / `style` / `nav` などを除いた文字を本文にする。`<main>` がない場合だけ Readability を使う。
- 一覧が複数のページに分かれている館は、巡回対象を複数登録する（国立西洋美術館の `current.html` と `upcoming.html`）。

## Alternatives
- 今のまま、初回の料金を受け入れる（終わった展示も読む）: 初回が$10〜20かかる。2012年までさかのぼった展示が大量に入り、行く展示を探すという使い方に合わない。
- 巡回でブラウザを動かし、JavaScript を実行してから読む: どのサイトにも効くが、1館のためには、GitHub Actions での巡回が重く遅くなりすぎる。
- 東京都現代美術館を当面、巡回から外す: ういぴさんが指定した館のうち1館が出ない。
- Readability のままにし、結果が短いときや会期がないときだけ `<main>` に切り替える: 2026italy のように、長いけれど中身が違う失敗を見分けられない。

## Consequences
- 初回の料金は7館で約$1になった（APIを67回）。登録された38件は、すべて開催中かこれからの展示だった。
- 本文の取り方を変えたので、既存のページのハッシュも変わる。変更後の最初の巡回では、全ページを1回ずつ抽出し直す。
- `<main>` に毎日変わる情報を入れているサイトがあると、毎日抽出し直すことになる。実際にそうなったら、そのとき直す。
- JSON の形や URL が変わると、気づかないうちに0件になることがある。0件が続いたら気づける仕組みは、後で足す。
- 国立西洋美術館の「コレクション・イン・フォーカス」は、会期の終わりが「2027年1月中旬予定」で日付にできず、展示として登録されない。
