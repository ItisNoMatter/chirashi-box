# 0032: 眺めるページのタブを、横スワイプでも切り替えられるようにする（指を離したときに判定）

- Date: 2026-10-13
- Status: Accepted
- Category: architecture
- Deciders: the user, Claude Code

## Context
ユーザーから、横スワイプで「開催中」「もうすぐ」を切り替えたいという要望があった。PWA でも、ブラウザのタッチイベントで実装できる。ただし次の3点に気をつける必要がある。
- エリアのチップの行は、横にスクロールする。
- 縦のスクロールと混ざらないようにする。
- iPhone では、画面の端からのスワイプが「戻る」の操作と重なることがある。

## Decision
- 指を離したときに1回だけ判定して、タブを切り替える（アプローチA）。画面は指に追従させない。
- 判定は純粋な関数 `swipeOf`（`src/ui/swipe.ts`）にまとめる。次の動きはスワイプにしない。
  - 横の動きが60px未満のもの
  - 横の動きが縦の1.5倍未満の、斜めの動き
  - 画面の左右の端（24px）から始まった動き
- スワイプはグリッドの上だけで受け取る。チップの行はこれまでどおり横にスクロールする。2本指の操作は判定しない。
- 左へスワイプすると右隣のタブ、右へスワイプすると左隣のタブに移る。端のタブではそれ以上進まない。切り替えは、タブを押したときと同じ処理を通す（押した瞬間に表示を切り替え、仮のカードを出す。0031）。

## Alternatives
- 2つのタブを横に並べ、CSS の scroll-snap で指に追従させる：ネイティブアプリに近い感触になる。ただし、両方のタブのデータを最初から読み込むことになる。0031 で速くしたばかりの表示がまた遅くなり、データベースへの問い合わせも倍になる。URL（`?tab=`）と表示を合わせるのも難しい。
- スワイプ用のライブラリ（Swiper、Embla など）を入れる：scroll-snap の案と同じく両方のタブを読み込む作りになり、依存と配信するコードも増える。

## Consequences
- 画面が指についてこないので、ネイティブアプリよりややそっけない感触になる。iPhone で触ってみて物足りなければ、指の動きに合わせてグリッドを少しずらす演出を足す。
- グリッドが短い（展示が少ない）ときは、スワイプを受け取れる範囲も狭くなる。
- 判定のしきい値（60px、1.5倍、24px）は、まだ実機で確かめていない。触ってもらって調整する。
