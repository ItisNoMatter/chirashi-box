# 0007: チラシ画像は館の画像URLを直接表示し、表示できなければ自動生成カードにする

- Date: 2026-10-11
- Status: Accepted
- Category: architecture
- Deciders: the user, Claude Code

## Context
チラシのデザインにも、そこに載っている作品画像にも著作権があり、許諾なしに自前で保存・配信すれば、複製と公衆送信にあたる（弁護士の判断ではない）。調査では、OGP画像（og:image）が取れたのは試した4館のうち2館（東京都美術館、森美術館）だけで、画像の形もポスターそのものとSNS用の横長画像とでバラバラだった。また、このアプリの核は「マイページにチラシが溜まり、会期が終わった展示も残る」ことだが、会期が終わると館がページや画像を消したり、URLを変えたりする可能性がある。

## Decision
- 画像は保存せず、館が指定した画像URL（主にog:image）を、ブラウザから館のサーバーへ直接読み込んで表示する。
- 画像が取れない場合や表示に失敗した場合は、展示名・会場・会期から自動生成したカードを表示する。
- 画像はトリミングせず、全体を表示する（`object-fit: contain`）。縦長でも横長でも崩れないカードにする。
- 画像の出どころを展示ごとに持ち、許諾を得た画像だけは保存して配信する経路を後から足せる作りにしておく。

## Alternatives
- 自前のサーバーを経由してキャッシュし、配信する: 終わった展示の画像も残り、表示も安定するが、キャッシュは複製と公衆送信にあたり、許諾がないうちは一番リスクが高い。
- 画像を使わず、自動生成カードだけにする: 権利上のリスクはゼロだが、「チラシが並ぶ楽しさ」というアプリの存在理由が大きく損なわれる。

## Consequences
- 会期が終わった展示の画像は、だんだん自動生成カードに置き換わっていく。これは受け入れる劣化とし、自動生成カードで見た目が崩れないようにする。
- 利用者が増えると、館のサーバーに直接負荷がかかる。直リンクを禁止している館では表示できない。規模が大きくなったら、それを美術館に広報用画像の許諾をもらう段階に進む合図とし、許諾を得た館の画像だけを保存・配信する経路に移す（0004の作り直しにはあたらない）。
- og:imageがない館（国立西洋美術館、国立新美術館など）は、最初から自動生成カードになる。
