# 0024: 認証メールは外部のSMTPで送る（まずBrevoを試す）

- Date: 2026-10-11
- Status: Accepted
- Category: tooling
- Deciders: the user, Claude Code

## Context
0008で、ホーム画面に追加したPWAではメールのリンクがSafari側で開いてしまうため、6桁の確認コードでログインすると決めた。ローカルでは確認コード入りのテンプレートで動作を確かめたが、本番のSupabase（無料プラン）にテンプレートを設定しようとすると、「無料プランで組み込みのメール送信サービスを使うプロジェクトでは、テンプレートを変更できない」というエラーで拒否された。既定のテンプレートにはリンクしかなく、確認コードが入っていない。

## Decision
Supabaseに外部のメール送信サービス（SMTP）を設定し、無料プランのまま確認コード入りのテンプレートを使う。まずはBrevoを試す。独自ドメインを取得したら、乗り換えを検討する。

## Alternatives
- Supabaseを有料プラン（Pro、月25ドル）にする: 設定の手間は一番少ないが、毎月の費用が今の規模に見合わず、組み込みの送信サービスの通数制限も残るので、いずれ外部SMTPが必要になる。
- 確認コードをやめ、メールのリンクでログインする方式に変える: 追加の作業も費用もないが、ホーム画面に追加したPWAではリンクがSafari側で開いてアプリ側でログインできず、iPhoneのPWAで使うという前提と矛盾する。
- Gmailのアプリパスワードで送る: 個人のGmailのアドレスが送信元として利用者に見える。
- Resendなど: 独自ドメインの認証が必要で、ドメインがない今は使えない。

## Consequences
- 外部サービスのアカウント作成と、送信元のアドレスの認証という作業が増える。
- 組み込みの送信サービスより送れる通数が多くなり、利用者が増えても対応できる。
- 本番のSupabaseに、SMTPの認証情報を設定する必要がある。
