# 0014: 「眺める」画面は開催中／もうすぐの2タブとエリア絞り込みにし、「近くで」と検索はMVPに入れない

- Date: 2026-10-11
- Status: Accepted
- Category: architecture
- Deciders: the user, Claude Code

## Context
前の会話では、最初のモック（タブ：開催中／もうすぐ／終了間近／近くで）と、簡略化した後の案（エリアと会期で絞り込む一覧）が混ざっていた。MVPの核は「展示を眺める → 気になるをマーク → マイページにチラシが並ぶ」。

## Decision
- 「眺める」には、開催中とこれから始まる展示を出す。終わった展示は出さない（マイページにだけ残る）。
- タブは「開催中」（終わるのが近い順）と「もうすぐ」（始まるのが近い順）の2つ。「終了間近」は独立したタブにせず、開催中の並び順と「あと◯日」の札で兼ねる。
- エリアは、会場の住所から自動で決まる「都道府県 → 市区町村」の2段階で絞り込む。
- 現在地を使う「近くで」は、MVPに入れない。
- キーワード検索は、MVPに入れない。ただし、展示名と会場名の検索を後から足しやすいDB設計にしておく。

## Alternatives
- モックどおり「終了間近」を独立したタブにする: 開催中を終わるのが近い順に並べれば同じ情報が先頭に来るので、タブを分ける意味が薄い。
- 「近くで」をMVPに入れる: Google Placesの規約上、座標を保存できる期間に制限がある可能性があり（0005）、規約を確認するまでは座標を前提にした機能を作らない。
- キーワード検索をMVPに入れる: 数十館の規模なら、エリアとタブで十分たどり着ける。ただし、規模が大きくなれば必要になるのは明らかなので（0004）、後から足せる設計にしておく。

## Consequences
- 会場の住所から都道府県と市区町村を取り出して持つ必要がある。これを保存してよいかも、0005の規約確認に含める。
- 「近くで」は、規約を確認して座標を持てると分かった時点で追加を検討する。
