# 0030: 1館でも巡回に失敗したら、巡回のジョブを失敗にする

- Date: 2026-10-13
- Status: Accepted
- Category: process
- Deciders: the user, Claude Code

## Context
巡回（`scripts/crawl.ts`）は、1館が失敗しても残りの館を続けて処理する。ジョブが失敗になるのは、すべての館が失敗したときだけだった。
2026-10-13 に大阪中之島美術館を追加して手動で巡回したところ、Anthropic API のクレジット残高が足りずにこの館だけが失敗した。ほかの館は一覧ページが変わっておらず API を呼ばなかったので、GitHub Actions の実行は「成功」と表示された。クレジット切れのように、続けて起きる失敗に気づけない作りになっていた。

## Decision
- 1館でも失敗したら、全館を処理して登録待ちの掃除も済ませてから、最後に終了コード1で終える。
- 失敗した館の名前と件数をエラーのメッセージに出す。
- 通知は GitHub Actions の「ワークフローが失敗したら通知する」既定の仕組みに任せる。

## Alternatives
- 今のまま（全館の失敗でだけ失敗にする）：クレジット切れのように、一部の館だけが目に見えて失敗するケースを見逃す。
- 失敗の通知を自前で送る（メールや Slack）：仕組みと秘密情報が増える。GitHub の失敗通知で足りる。

## Consequences
- 1館のサイトが一時的に落ちているだけでもジョブが赤くなる。誤報が増えるが、ログで館名がわかり、次の晩に自動で再試行される（一覧ページのハッシュは最後まで処理できた館にしか保存しない）。誤報が多すぎたら、連続で失敗したときだけ赤くする案を検討する。
- 残高のアラートは Anthropic Console の側で、ユーザーが設定する。
