# 0010: 巡回では、新しいページと変わったページだけをLLMで抽出する

- Date: 2026-10-11
- Status: Accepted
- Category: architecture
- Deciders: the user, Claude Code

## Context
巡回は「会場の一覧ページ → 個別の展示ページ → LLMで抽出」という流れになる。毎日すべてのページをLLMに通すと、コストが「会場数 × 展示数 × 日数」で増え、会場を増やすほど毎日の請求が比例して膨らむ（0004に反する）。

## Decision
- 一覧ページは毎日取得し、主要部分のハッシュが前回と同じなら、その会場はそこで終える。
- 一覧から集めた個別ページのURLのうち、`exhibition_sources` にない新しいものだけをLLMで抽出する。
- 既知のページは取得だけして、主要部分のハッシュを比べ、変わっていたらLLMで抽出し直す。
- 会期が終わった展示のページは、もう取得しない。
- ハッシュは、Readability等で本文の主要部分だけを取り出してから計算する。

## Alternatives
- 毎日すべての個別ページを取得し、LLMで抽出し直す: 単純で会期の変更も必ず拾えるが、変わっていないページを毎日LLMに通すことになり、会場を増やすほど無駄なコストが比例して増える。

## Consequences
- LLMのコストは、新しく出た展示と変わった展示の数にしか比例しない。
- 終わった展示を取得しないので、館のサーバーへの負荷も減る。
- 日付やおすすめ欄のように、展示と関係なく毎日変わる部分があると、差分の判定が効かない。主要部分の抽出で抑えきれない館は、その館だけ無駄にLLMに通る（正しさは損なわれない）。
- ハッシュの保存と比較のロジックが増える。
